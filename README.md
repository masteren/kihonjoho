## 一、最需要优先复习的领域

### 1. 信息安全（优先级最高）

错题中信息安全相关题目占比最高，是当时最明显的薄弱点。

主要问题不是完全不懂，而是容易把功能相近的术语混在一起。例如检测、防止、证明、攻击手法、风险应对方式之间的边界不够清楚。

**需要重点复习：**

| 分类 | 内容 |
|---|---|
| 攻击手法 | SQL 注入、目录遍历、跨站脚本、暴力破解、DoS / DDoS |
| 检测与防御工具 | IDS、IPS、防火墙、WAF、杀毒软件、脆弱性诊断、ファジング |
| 认证与证明 | 数字签名、电子证书、时间戳服务、哈希、公开密钥加密 |
| 风险管理 | 风险回避、风险低减、风险移转、风险受容 |

**复习建议：** 不要只背定义，要用「关键词区分法」。

| 关键词 | 对应概念 |
|---|---|
| 检测、通知 | IDS |
| 阻断、防止 | IPS |
| 路径、文件、上层目录 | 目录遍历 |
| 随机输入、异常输入、找漏洞 | ファジング |
| 某时刻存在、未篡改 | 时间戳服务 |
| 保险、外包 | 风险移转 |
| 停止风险原因 | 风险回避 |

> 这一块每天单独复习 20–30 分钟、连续几天，比一次性看很多更有效。

### 2. 服务管理与 BCP（优先级高）

这个领域的特点是术语很多，而且中文直觉不一定可靠。

**当时暴露的问题：**

- 对 incident 的范围理解偏窄。
- 对 BCP、RTO、MTBF、MTTR 等恢复相关术语区分不够稳定。
- 容易只按字面猜，而没有抓住考试中的固定定义。

**需要重点复习：** インシデント、問題管理、変更管理、サービスレベル管理、BCP、RTO、RPO、MTBF、MTTR。

**复习建议：** 适合做「术语对照表」，不要散着背。

| 术语 | 重点理解 |
|---|---|
| Incident | 服务计划外中断、质量下降、可能影响服务的事件 |
| Problem | incident 背后的根本原因 |
| RTO | 到恢复为止的目标时间 |
| RPO | 允许丢失到哪个时间点的数据 |
| MTBF | 平均多久故障一次 |
| MTTR | 平均修多久 |

> 每个术语都配一个简单例子。只背英文缩写很容易忘。

### 4. 数学与计算量（优先级中）

数学题数量不多，但错题说明在「比例关系」和「计算量阶数」上需要更谨慎。

**当时的问题：**

- 容易把「几倍」当成线性变化。
- 看到「三次方に比例」时，没有马上转换成计算量思维。

**需要重点复习：** 比例计算、指数增长、O(n) / O(n²) / O(n³)、处理时间与数据量的关系。

**固定步骤：**

1. 原来的规模是多少。
2. 新的规模是多少。
3. 规模变成几倍。
4. 时间是线性、平方还是三次方变化。
5. 最后再考虑机器速度变快或变慢。

例如规模变成 10 倍：

| 计算量 | 时间变化 |
|---|---|
| O(n) | 10 倍 |
| O(n²) | 100 倍 |
| O(n³) | 1000 倍 |

## 二、错题反映出的主要问题

### 问题 1：相近术语区分不够清楚

这是最主要的问题。比如：

- IDS 和 IPS
- 风险回避、低减、移转
- RTO、MTBF、MTTR
- RAM、ガントチャート、トレンドチャート

这些题不是靠感觉选，而是靠关键词判断。复习时要多做「对比记忆」，不要单独背一个词。

### 问题 2：日语术语看懂了，但考试定义没有固定

有些词看起来能理解，但考试问的是固定定义。

例如 incident 不只是系统完全停止，也包括服务质量下降，甚至包括将来可能影响服务的状态。

这说明复习时不能只靠中文直觉，要把 IPA 考试中的标准说法记住。

### 问题 3：看到计算题时容易漏掉条件

数学题本身不复杂，但需要注意题目中的限制条件。例如：

- 与未知数个数的三次方成比例
- 电脑速度变成 4 倍

这种题错了通常不是不会算，而是没有按步骤整理条件。

## 六、知的财产权、相关法规、标准化组织

这两题都属于「知的財産権・関連法規・その他」的范围，不是计算题，而是典型的术语和制度判断题。

### 1. 製造物責任法和软件、数据

题目问：软件或数据有瑕疵时，哪一个属于製造物責任法的对象。

**关键点：**

- 製造物責任法主要针对「製造または加工された動産」，也就是制造、加工出来的有形动产。
- 软件、数据本身通常不是製造物責任法中的「製造物」。
- 但如果软件被 ROM 化并内置在机器中，作为机器的一部分销售，那么对象是这个「内置软件的设备」。

| 关键词 | 判断 |
|---|---|
| ソフトウェア単体 | 通常不是 PL 法对象 |
| データ単体 | 通常不是 PL 法对象 |
| ダウンロードデータ | 通常不是 PL 法对象 |
| ROM 化したソフトウェアを内蔵した機器 | 属于対象 |

**正确方向：ROM 化したソフトウェアを内蔵した組込み機器。**

**相关错题：** [03 製造物責任法](images/03_制造物责任法_嵌入式软件瑕疵.png)

### 2. RFC 和 IETF

题目问：制定互联网技术标准，并把技术规格作为 RFC 发布的是哪个组织。

**关键点：** RFC 是互联网相关技术规范文件，IETF 负责互联网技术标准化并发布 RFC。

容易混淆的组织：

| 组织 | 重点 |
|---|---|
| ANSI | 美国国家标准 |
| IEEE | 电气、电子、LAN、无线等标准，例如 IEEE 802 |
| IETF | 互联网技术标准，RFC |
| NIST | 美国标准技术研究所，安全标准和技术指南等 |

**正确方向：IETF。**

**相关错题：** [09 IETF / RFC](images/09_IETF_RFC互联网标准化组织.png)

### 追加复习建议

「法规、标准化组织」也需要补一个小表。这个领域出题频率不一定最高，但很适合短时间提分，因为基本都是固定对应关系。

| 关键词 | 对应概念 |
|---|---|
| 製造物責任法、動産、組込み機器 | PL 法 |
| RFC、互联网技术规格 | IETF |
| LAN、无线、IEEE 802 | IEEE |
| 美国标准 | ANSI |
| 美国技术标准、安全指南 | NIST |

## 七、软件测试手法

这部分错题全部来自「テスト・レビュー・修正」领域，是之前没有专项整理的薄弱板块。

### 1. ホワイトボックステスト：命令網羅 vs 判定条件網羅

两者都是白盒测试的覆盖率指标，但不是同一层级。

| 术语 | 定义 | 关键词 |
|---|---|---|
| 命令網羅 | 所有命令至少执行一次 | 命令、実行 |
| 判定条件網羅 | 所有分支各走一次（True / False 都走到） | 分岐、True / False |

**重要关系：判定条件網羅の方が命令網羅より網羅度が高い。**

原因：如果某个分支中没有命令，命令網羅无法检测该分支，但判定条件網羅可以。因此满足判定条件網羅时，命令網羅一定也被满足；反之不成立。

**相关错题：** [13 網羅度比較](images/13_命令網羅_判定条件網羅_網羅度比較.jpeg)

### 2. 判定条件網羅 → 複数条件網羅 的区别

| 术语 | 定义 |
|---|---|
| 判定条件網羅 | 每个判断整体的 True / False 都覆盖 |
| 複数条件網羅 | 每个判断中每个子条件的所有组合都覆盖（TT、TF、FT、FF） |

例如条件 `A>6 or B=0`：

- 判定条件網羅：整体为 True 和 False 各一次即可
- 複数条件網羅：需要覆盖 (A>6=T, B=0=T)、(T,F)、(F,T)、(F,F) 四种组合

从判定条件網羅升级到複数条件網羅时，需要追加能让子条件组合出现新情况的测试数据。

**相关错题：** [14 テストデータ追加](images/14_判定条件網羅_複数条件網羅_テストデータ.jpeg)

### 3. 判定条件網羅 の最小テストケース数

规则：判定条件網羅只需 **2 个测试用例** 即可 —— 让所有分支同时走 True 路径、同时走 False 路径。

例如流程图有 2 个判断节点：

- テストケース 1：两个判断都走 True
- テストケース 2：两个判断都走 False

最小テストケース数 = **2**（与分支数量无关，只看「能否让每个分支都覆盖到」）。

**相关错题：** [17 最小テストケース数](images/17_判定条件網羅_最小テストケース数.jpeg)

### 4. ブラックボックステスト：同値分割 vs 境界値分割

| 手法 | 定义 | 关键词 |
|---|---|---|
| 同値分割 | 把输入范围分成若干等价组，每组取一个代表值 | グループ、代表値 |
| 境界値分割 | 在各组的边界值前后取测试数据 | 境界、境目 |

ブラックボックステスト：只关注输入和输出，不验证程序内部结构。

**相关错题：** [15 同値分割 / 境界値分割](images/15_ブラックボックステスト_同値分割_境界値分割.jpeg)

### 5. ドライバ vs スタブ

结合测试时，因为不能一次性把所有模块都做好，需要用「假模块」代替未完成的部分。

| 术语 | 用在哪里 | 替代谁 | 作用 |
|---|---|---|---|
| ドライバ（Driver） | ボトムアップテスト | 仮の上位モジュール | 向下位模块传递参数并调用它 |
| スタブ（Stub） | トップダウンテスト | 仮の下位モジュール | 对上位模块的调用返回适当的值 |

**记忆方法：**

- Bottom-Up（从下往上）→ 上面没做好 → 需要假的「上司」→ **Driver**
- Top-Down（从上往下）→ 下面没做好 → 需要假的「部下」→ **Stub**

**相关错题：** [16 ドライバ / スタブ](images/16_ドライバ_スタブ_結合テスト.jpeg)

## 八、SQL データ操作

### SQL 暗黙的結合（カンマ JOIN）

题目中出现的 SQL：

```sql
SELECT 氏名 FROM 学生, 学部
WHERE 所属 = 学部名 AND 学部.住所 = '新宿'
```

**解读：**

- `FROM 学生, 学部` 是隐式 CROSS JOIN，用 WHERE 条件过滤
- `所属 = 学部名` 是连接条件（等价于 INNER JOIN ON）
- `学部.住所 = '新宿'` 是过滤条件

**做题步骤：**

1. 先找出满足 `学部.住所 = '新宿'` 的学部名：工、理
2. 再找出所属是工或理的学生：情報太郎（工）、応用花子（理）

> **易错点：** 不要看学生自己的住所列，要看学部表的住所列，然后通过「所属」列做对应。

**相关错题：** [18 暗黙的 JOIN](images/18_SQL_暗黙的JOIN_WHERE.jpeg)

## 九、期待値計算

### 初年度の修正費用の期待値

这类题是标准的「期望值 = 概率 × 金额」计算，步骤固定。

**例题条件：**

| 条件 | 数值 |
|---|---|
| プログラム規模 | 2,000 k ステップ |
| 潜在不良率 | 0.04 件 / k ステップ |
| 年間発見率 | 20 % / 年 |
| 影響度大の割合 | 20 % |
| 影響度小の割合 | 80 % |
| 影響度大の修正費用 | 200 万円 |
| 影響度小の修正費用 | 50 万円 |
| 初年度の方針 | 影響度大の不良だけを修正する |

**计算过程：**

1. 総潜在不良数：2000 × 0.04 = **80 件**
2. 初年度に発見される不良数：80 × 0.2 = **16 件**
3. その中の影響度大：16 × 0.2 = **3.2 件**
4. 初年度の修正費用：3.2 × 200 = **640 万円**

> **注意：** 题目说「初年度は影響度大だけを修正する」，所以影響度小的费用不计入。

**固定步骤：** 规模 × 不良率 → 总潜在 → × 发现率 → 初年度发现 → × 分类比例 → × 单价。

**相关错题：** [19 期待値計算](images/19_初年度修正費用_期待値計算.jpeg)

---

## 十、结语与完结

这些错题反映出的最大问题是：基础概念大致知道，但相近术语的边界不够清楚。

有效的做法不是按单题背答案，而是按「领域 + 易混概念 + 关键词」复习。尤其是信息安全和服务管理这两块要优先补强；法规和标准化组织可以用小表快速记忆，投入时间少，但容易稳定拿分。只要把术语对照整理清楚，这类题的正确率会明显提高。

**完结：基本情報技術者試験 已合格。**

本仓库到此结束，作为备考过程的记录保留，不再继续更新。上面的错题分类、术语对照表和固定解题步骤对同样在准备基本情報的人应该仍然有参考价值 —— 特别是「关键词区分法」这一条，是整个复习中收益最大的方法。

祝各位顺利合格。
